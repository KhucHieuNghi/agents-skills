# Problem Presentation

Turn one problem into a decision-ready, self-contained HTML presentation. Keep
the problem narrow enough that the audience can act after one viewing.

## Frame the decision

Identify the audience, the observed problem, why it matters to them, the
available evidence, and the decision requested. Infer missing context from
provided material when safe; ask only when the problem or decision cannot be
identified. Separate observed facts, interpretation, and proposals. Label
unverified claims as hypotheses and never invent metrics, customer quotes, or
certainty.

## Build the presentation

Use about five short slides: decision question, visual explanation, evidence,
consequences and options, and the exact ask. Adjust the count if clarity
requires it. Keep one message per slide. Include one diagram only when it
explains a relationship, sequence, or gap better than text; label its nodes and
connections, and provide an accessible text description. If a diagram would
add no information, use a table or sentence and explain that choice.

Generate one local HTML file that opens without network access. Use system
fonts and inline or local assets. Make text readable when projected and on a
phone without page-level horizontal overflow; support keyboard navigation,
deep links, and print. Put a compact source link or reference beside each
consequential factual claim and collect sources at the end. Keep source names
visible if the HTML is moved away from its source files. Never place
credentials or private customer data in the artifact.

If a vetted presentation or diagram skill is installed, use it where it
improves this specific output; keep this skill's evidence and decision contract
authoritative. Do not require an unreviewed public component or an external
service to finish the presentation.

## Check before delivery

Read the presentation as the intended audience: can they name the single
problem, distinguish evidence from inference, and answer the requested
decision? Check every factual claim against its source, inspect the diagram for
misleading arrows, open the HTML at desktop and narrow widths when a browser is
available, and verify that it works offline. Report any unchecked visual or
source claim instead of calling the deck ready.
