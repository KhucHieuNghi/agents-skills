# Direction and implementation

## Taste Skill direction

Before coding, state the page's central argument in one sentence. Sketch a
sequence of visual beats that takes the visitor from the problem to the offer
and next action. Select one subject-specific organizing idea with a reason the
audience would recognize. Define desktop and narrow-screen reading order, the
hero focal point, and what evidence the page needs to show. Reuse an approved
direction on an existing page and record the scope of any proposed departure.

## Frontend Design implementation

Make the direction visible in typography, spacing, hierarchy and composition.
Use approved colors and assets. Translate the visual idea into a stable layout
before adding motion. Use concrete product images, photography or diagrams
where they communicate information. Confirm their provenance or use an
explicitly provisional local treatment. Avoid visual novelty that obscures
reading, primary actions or keyboard focus.

Use the existing framework, routes, components, styles and test commands. In an
empty project, use portable semantic HTML and CSS unless the brief calls for a
framework. Keep content translation aligned with the site's locale mechanism.
Avoid embedding unrelated credentials, trackers, dependencies or remote assets.
Use real links for navigation and buttons for actions. Include accessible form
labels, useful errors, and a truthful success state where applicable. Preserve
existing routes and integrations within the scope of the work.

Keep page title, description, language, link destinations and share metadata
consistent with the actual offer and deployment context. Use a canonical URL
only when the publish destination is known. Keep previews private or use an
approved preview configuration before exposing them. A conversion measurement
plan can describe event names, trigger, owner, and validation without collecting
events. Add integration only when authorized and follow the customer's consent
and data handling requirements.
