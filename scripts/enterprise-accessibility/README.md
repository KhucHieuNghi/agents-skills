## Attributed scenario predicates

`scenario-rules.mjs` is an internal pure decision layer, not an evidence importer or customer command. evaluateScenarioRule(ruleId, facts, context) validates typed scalar facts and returns a declared-step draft result, criterion reference (or null for product journey diagnostics), and the exact usedFacts dependencies. A caller must first validate source scope, author attribution, attachments and per-fact freshness using the [scenario contract](../../docs/plans/website-audit-enterprise-accessibility-scenarios.md). The development importer is now implemented in scenarios.mjs; full manual coverage and commercial acceptance remain open. Never present a direct predicate result as authenticated evidence or independent acceptance.

The predicate registry covers keyboard exit/operation, focus visibility/order/obscuration, error identification, dialog naming, reflow, error recovery and terminal journey outcome. Sandbox/production scope is predeclared; missing/mismatched outcomes are unknown. Unknown facts never become false. Standard exit availability false means reviewed absence, not unreviewed. Automatic author-created overlays do not gain the exception intended for persistent content opened by the user.

`tests/browser/enterprise-accessibility.mjs NEW_OUTPUT` collects nine loopback-only Chromium scenarios, exact focus/action/DOM traces and screenshot hashes. The single POST is to a synthetic local failing-booking endpoint. It does not generate criterion verdicts or simulate screen-reader evidence. Finite Tab/Escape traces and three hit-test points do not establish full keyboard or visual coverage. Use source inspection and attributed semantic review for those judgments. Run predicate tests with `npx vitest run tests/content-audit-accessibility-scenarios.test.ts --maxWorkers=1`.

## Scenario trace import

`scenarios.mjs` exports evaluateAccessibilityScenarios(context, sources). It reads supplied bytes only and performs no network, browser or filesystem action. The [strict contract](../../docs/plans/website-audit-enterprise-accessibility-scenarios.md) defines all context, source, attachment and fact fields. Every predeclared step/rule is accounted for, including unvisited steps. Unknown requests identify customer/entity/environment, URL/state/device/protocol, expected outcome scope, required fact names, freshness and owner/fallback.

Facts expire at the earliest supporting attachment or step timestamp plus maxAgeSeconds, exclusively. Original values remain in normalized records for traceability; evaluation masks expired facts to null. Static contradictions are rejected before masking. Neither recent capture nor recent interpretation refreshes original evidence. Current fact conflicts are resolved before aggregation, with conflicting values masked separately in each source. A sufficient independent failure remains possible; partial traces are never combined to assemble a pass. Browser/assistive-technology/input-mode populations remain separate. Aggregate checks include per-source resolutions, dependencies, expiry and conflict names; original per-trace checks are not the final aggregate verdict.

Source reformatting does not add unique traces; all source aliases and supplied author identities remain visible. Author type human or ai-assisted is always supplied-attribution, never authenticated identity or an independent review decision. Raw attachments/browser strings are excluded from normalized output. Attachment hashes prove byte bindings, not that an image description is a verified screenshot or a business outcome is authenticated. Full coverage, execution authentication, conformance and semantic acceptance remain false/unknown.

Run `npx vitest run tests/content-audit-accessibility-traces.test.ts --maxWorkers=1`. `node tests/browser/enterprise-scenario-import.mjs NATIVE_TRIAL NEW_OUTPUT` imports the nine retained loopback fixture traces with explicit root AI interpretations. It requires the preceding browser harness's private directory and verifies native hashes. It is a fixture reproducer, not a customer collector or independent manual review. Keep its native/input/result JSON private; customer reports use the P2 workflow below and require independent review.

## Canonical source-run integration

`workflow.mjs` exports evaluateEnterpriseAccessibility(sourceDirectory, bundle, newDirectory). It forks P2 state and saves an immutable revision after validation; existing output is refused. The [integration contract](../../docs/plans/website-audit-enterprise-accessibility-report.md) defines entry windows, scope identity, cache ownership and report semantics. Use returned findings/observations with buildEnterpriseReport/saveEnterpriseReport. Retain independently valid findings/actions from other modules explicitly. Counts are historical supplied-record snapshots, not quality scores or authenticated execution counts; preserve the parent's observations when creating a report revision.

The source run owns customer identity and the bundle owns assessmentAt. Each entry declares a completed half-open observation window; native axe timestamps and scenario step/attachment observations must fit. Checks keep state/device/protocol/window and expected outcome scope visible. Product journey diagnostics use ux-cro, not a WCAG criterion. Manual coverage remains an unknown check with concrete requests even if all supplied checks pass. Declined requests retain owner attribution.

All retained evaluations are rebuilt from raw bytes, including entries absent from a new bundle. Indexes cannot authorize deletion: ownership, cached content/expiry, check dependencies and request mappings are reconstructed and validated. Removing an index together with checks while retaining base evidence still fails; superseded rollback pointers fail. Canonical obligation ordering does not duplicate checks. Same-population overlapping obligation lists under different IDs are rejected.

Findings are low-confidence drafts based on supplied evidence. Old independent verdict timestamps cannot be copied into a new assessment; obtain fresh target-bound decisions. The packaged offline CLI is now wired; candidate freeze and fresh-install verification are recorded separately. Run `npx vitest run tests/content-audit-accessibility-workflow.test.ts --maxWorkers=1`. The optional local reproducer `node tests/browser/enterprise-accessibility-report.mjs AXE_TRIAL TRACE_IMPORT NEW_OUTPUT` builds/revises canonical reports from retained native fixtures and checks desktop/mobile rendering; it is not a native-host or production trial.
