# Accessibility development foundation

Original implementation of [P5 accessibility](../../docs/plans/website-audit-enterprise-accessibility.md), outside the released skill package. Candidate 0.3.12 remains unchanged. This is not the full accessibility module or customer CLI.

`axe.mjs` exports normalizeAxe(input, context) and evaluateAxe(context, inputs). Inputs are exact supplied native axe-core 4.14.1 JSON, hashed and bound to customer/entity/environment/URL/state/viewport/capture time. Assessment freshness is exclusive at native timestamp plus maxAgeSeconds; recapturing old results does not refresh them. The strict input contract and bounds are in the linked plan.

Results are limited to **reported-tested-elements**, including passes. Native AxeResults does not carry the invocation include/exclude context, and toolOptions does not prove effective axe.configure overrides. configurationProvenance and page coverage remain unknown; a concrete request asks for invocation context/configuration and scoped manual review. No WCAG criterion mapping, conformance verdict or authenticated execution is inferred. The development identityDigest is not a final P2 check identity.

The same rule can contain passing and failing nodes: all categories are retained, with failure taking precedence within one scan. Incomplete remains unknown unless the scan also reports violations. Across conflicting eligible scans or different browser/options populations, the current rule check is unknown and each record remains visible. Missing, stale, unsupported and inapplicable-only records never produce a pass. Raw HTML/selectors/messages are excluded from normalized output; target/HTML hashes preserve private evidence linkage. Node counts mean reported nodes only: resultTypes filtering can truncate unselected categories. Unique measurement count deduplicates semantic exports; it does not authenticate independent executions.

## Attributed scenario predicates

`scenario-rules.mjs` is an internal pure decision layer, not an evidence importer or customer command. evaluateScenarioRule(ruleId, facts, context) validates typed scalar facts and returns a declared-step draft result, criterion reference (or null for product journey diagnostics), and the exact usedFacts dependencies. A caller must first validate source scope, author attribution, attachments and per-fact freshness using the [scenario contract](../../docs/plans/website-audit-enterprise-accessibility-scenarios.md). The development importer is now implemented in scenarios.mjs; canonical P2 integration remains open. Never present a direct predicate result as authenticated evidence or independent acceptance.

The predicate registry covers keyboard exit/operation, focus visibility/order/obscuration, error identification, dialog naming, reflow, error recovery and terminal journey outcome. Sandbox/production scope is predeclared; missing/mismatched outcomes are unknown. Unknown facts never become false. Standard exit availability false means reviewed absence, not unreviewed. Automatic author-created overlays do not gain the exception intended for persistent content opened by the user.

`tests/browser/enterprise-accessibility.mjs NEW_OUTPUT` collects nine loopback-only Chromium scenarios, exact focus/action/DOM traces and screenshot hashes. The single POST is to a synthetic local failing-booking endpoint. It does not generate criterion verdicts or simulate screen-reader evidence. Finite Tab/Escape traces and three hit-test points do not establish full keyboard or visual coverage. Use source inspection and attributed semantic review for those judgments. Run predicate tests with `npx vitest run tests/content-audit-accessibility-scenarios.test.ts --maxWorkers=1`.

## Scenario trace import

`scenarios.mjs` exports evaluateAccessibilityScenarios(context, sources). It reads supplied bytes only and performs no network, browser or filesystem action. The [strict contract](../../docs/plans/website-audit-enterprise-accessibility-scenarios.md) defines all context, source, attachment and fact fields. Every predeclared step/rule is accounted for, including unvisited steps. Unknown requests identify customer/entity/environment, URL/state/device/protocol, expected outcome scope, required fact names, freshness and owner/fallback.

Facts expire at the earliest supporting attachment or step timestamp plus maxAgeSeconds, exclusively. Original values remain in normalized records for traceability; evaluation masks expired facts to null. Static contradictions are rejected before masking. Neither recent capture nor recent interpretation refreshes original evidence. Current fact conflicts are resolved before aggregation, with conflicting values masked separately in each source. A sufficient independent failure remains possible; partial traces are never combined to assemble a pass. Browser/assistive-technology/input-mode populations remain separate. Aggregate checks include per-source resolutions, dependencies, expiry and conflict names; original per-trace checks are not the final aggregate verdict.

Source reformatting does not add unique traces; all source aliases and supplied author identities remain visible. Author type human or ai-assisted is always supplied-attribution, never authenticated identity or an independent review decision. Raw attachments/browser strings are excluded from normalized output. Attachment hashes prove byte bindings, not that an image description is a verified screenshot or a business outcome is authenticated. Full coverage, execution authentication, conformance and semantic acceptance remain false/unknown.

Run `npx vitest run tests/content-audit-accessibility-traces.test.ts --maxWorkers=1`. `node tests/browser/enterprise-scenario-import.mjs NATIVE_TRIAL NEW_OUTPUT` imports the nine retained loopback fixture traces with explicit root AI interpretations. It requires the preceding browser harness's private directory and verifies native hashes. It is a fixture reproducer, not a customer collector or independent manual review. Keep its native/input/result JSON private; customer reports require P2 integration and review.
