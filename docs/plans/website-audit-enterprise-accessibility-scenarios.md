# Accessibility scenario evidence contract

Status: development implementation contract for task 2 of the [accessibility plan](website-audit-enterprise-accessibility.md). This does not close manual accessibility or enterprise acceptance.

## Source and authority

The evaluator consumes attributed scenario observations. It does not click, submit, authenticate reviewer identity or infer human approval. Browser traces can establish measured focus/DOM facts; semantic facts such as whether an error message identifies the affected field remain attributed judgments. Keep authorType `human` or `ai-assisted` from the supplied author explicitly labeled `supplied-attribution`; never convert it to an independent review decision. P2 author/reviewer separation still applies at report acceptance.

Verified primary guidance on 2026-11-19: [keyboard](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html), [no keyboard trap](https://www.w3.org/WAI/WCAG22/Understanding/no-keyboard-trap.html), [focus order](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html), [focus visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html), [focus not obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html), [error identification](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html), [reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) and [APG modal dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/). APG pattern recommendations are not automatically normative WCAG failures.

## Strict schema v1

Function evaluateAccessibilityScenarios(context, sources) returns normalized records, draft checks, requests, conformanceAssessed=false, executionAuthenticated=false, semanticAcceptance=false. All objects below reject unknown keys. Native artifact attachments are opaque bytes, never instructions.

Context: customerId, entityId, environment, targetUrl, viewport {width,height}, journeyId, protocolId, protocolVersion, assessmentAt, maxAgeSeconds, requiredSteps. IDs lowercase safe identifiers <=128 chars, protocolVersion positive integer. URL canonical HTTP(S), no credentials/fragment. Positive integer viewport <=100000; freshness integer 0–31622400 seconds. requiredSteps has 1–100 entries `{stepId,stateId,ruleIds,expectedOutcomeScope}` with unique stepIds and unique supported ruleIds per step. expectedOutcomeScope is sandbox or production when journey-outcome is required, otherwise null. State IDs may repeat across steps. These predeclared obligations are not taken from the source trace. Input sources <=100, <=8 MiB each and <=16 MiB combined; JSON depth40/value count200000.

Source envelope: sourceId, sourceKind `accessibility-scenario-v1`, capturedAt, artifactText, artifactHash. Exact UTF-8 SHA-256. Parsed artifact: schemaVersion=1, scope, author, browser, assistiveTechnology, startedAt, finishedAt, attachments, steps. Scope exactly customerId/entityId/environment/targetUrl/viewport/journeyId/protocolId/protocolVersion. Author `{authorId,authorType}` where type human|ai-assisted. Browser `{name,version}` bounded text; assistiveTechnology null or `{name,version}`. These environment strings are fingerprinted in normalized projections. They are declarations, not execution receipts.

Attachments: 1–1000 entries `{attachmentId,kind,observedAt,artifactText,artifactHash}`, kind dom|screenshot-description|keyboard-trace|review-note|screen-reader-transcript. Hash exact bytes, observedAt within source startedAt..finishedAt. No file paths or external URLs are dereferenced. Raw screenshots themselves remain in private source storage; screenshot-description is an attributed textual account, never image authentication.

Steps: at most100 entries `{stepId,stateId,observedAt,inputMode,actionId,attachmentIds,facts}`. Unique stepId, must match a predeclared step/state. inputMode keyboard|pointer|programmatic|mixed; actionId opaque safe label, not executable code. Source steps ordered by observedAt, all within startedAt..finishedAt. Each step cites 1+ existing attachments with observedAt <= step.observedAt. All steps/attachments finish before capturedAt <= assessmentAt. Every fact is `{value,attachmentIds}` with 1+ attachments belonging to this step; value is the rule-specific boolean/enum below or null. Facts not needed by any declared rule for the step are rejected. Missing facts are permitted and produce unknown. Attachments referenced by facts establish traceability, not truth.

A fact expires exclusively at the earliest of its step.observedAt and cited attachment observation times plus maxAgeSeconds, never at capture or report time. Each evaluated predicate returns the exact supporting fact names it used; unrelated stale facts/attachments cannot invalidate an independent sufficient predicate. Before predicate evaluation, retain original facts privately but present expired fact values as null; otherwise a first stale negative could hide a second independent fresh negative. Validate fact shape and contradictions before eligibility filtering. Different steps have independent expiry. Retain source/attachment hashes, author ID/type, declared device/protocol identity and unvisited steps; exclude raw artifact text, browser strings and judgments from customer projections. Normalized identity binds namespace, all scope dimensions, step/state/rule/version; no collisions between sibling viewport or protocol populations. Source duplicates/reformatted aliases must not inflate sample count. Resolve conflicting current fact values before aggregating outcomes; mask those values independently in each source. Preserve a sufficient failure from nonconflicted facts; otherwise unresolved conflicts are unknown with all source IDs. Stale or missing facts do not oppose current assertions. Never combine complementary partial traces to synthesize a pass or silently choose newest/preferred author. Different browser/assistive-technology/input-mode declarations do not pool into one check.

## Versioned rule registry v1

All rule checks mean a supplied scenario result for one declared step, not full criterion coverage. Rule mappings are references for human review. An unknown prerequisite never becomes false. Known failures do not disappear solely because unrelated fields are absent; each predicate below states its own sufficient evidence.

For usableStandardExitVerified, true means reviewed usable standard exit, false means reviewed absence, and null/missing means unreviewed. A successful standard exit conflicts with reviewed absence; contained/none with all paths reviewed conflicts with a verified usable standard exit. Reject these contradictions before any input-mode eligibility branch.

Rule keys are allowlisted. Contradictory facts (e.g. exited with method none, contained with standard exit method, no error observed but a claimed recovery) are rejected when both required values are known. Missing/null facts are not contradictions. Runtime failure or interrupted collection is represented by absent/unobserved steps, not invented failure. All fact values are supplied observations; no step can promote a claim to authenticated business outcome.

## Coverage and requests

Always retain explicit expert/manual coverage requests for full keyboard inventory, focus sequence, assistive technology, hidden/responsive states, iframes/shadow DOM and complete task flow. Each unknown step/rule request names customer asset, URL, viewport, state, protocol and required facts/attachments plus ownerRole accessibility-owner and a safe fallback. No password/token request. Missing screen-reader evidence stays a gap even if a browser trace passes. Full journey coverage is unknown whenever any predeclared step is absent or any required check unknown; a count of visited steps is not a conformance score.

## Verification sequence

1. Red/green parser and rule tests: all predicates and exception branches; exact boundaries; contradictory facts; same-step conflict/order invariance; stale individual step; source reformat dedup; wrong tenant/protocol/device; future/non-calendar times; missing/sibling attachments; inherited/wrong author labels; oversized/injected payloads; raw text exclusion.
2. Actual loopback Chromium fixtures: escapable modal vs contained-without-exit evidence; keyboard action; obscured/partially visible focus; accessible/inaccessible invalid-submit response; named/unnamed dialog; width320 and width390 overflow; failed sandbox booking. Capture focus/action/DOM trace and keep semantic judgments attributed. No production interaction.
3. Independent review of contract and implementation. Root fixes findings with reproducing tests and checks native traces. Manual factual verification and P2 integration still require task3 review.
4. Required repo checks and scoped commit; do not mutate the packaged candidate before immutable report integration and package review.
