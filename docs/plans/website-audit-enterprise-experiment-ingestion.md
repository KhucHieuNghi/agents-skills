# Original experiment evidence ingestion contract

Status: design in review, implementing task 3 of the [experiment plan](website-audit-enterprise-experiments.md). This is a supplied-export adapter, not live provider acquisition or completed enterprise acceptance.

## Interface and ownership

Implement `evaluateExperimentExports(context, sources)` in `scripts/enterprise-journeys/experiments.mjs`. It reuses the strict capture JSON parser, enterprise canonical digest and existing decision/accounting predicates. `tests/content-audit-experiment-exports.test.ts` exercises original bytes and eligibility; fixtures cover all five business profiles and a mixed case before workflow closure.

Context exact fields: scope, protocol, protocolDigest, assessmentAt, maxAgeSeconds, ingestionLagSeconds. Scope exact customerId/entityId/environment/experimentId. All IDs are bounded identifiers; environment is sandbox or production. Protocol is retained in full, and protocolDigest equals its canonical digest. Changing any method, definition, horizon, margin, cohort, enrollment or stopping rule invalidates earlier exports. Assessment and every timestamp use validated real UTC calendar timestamps; maxAgeSeconds and ingestionLagSeconds are bounded whole seconds, freshness positive.

Protocol exact fields: decision, registration, assignment, population, enrollment, metrics, stopping, synthetic. Decision is the complete existing experiment-decision protocol, including cohortDigest and family. Registration has registeredAt, locator and artifactHash; these are attributed declarations, not independent proof of chronology. Assignment has unit, identityRule, bucketingRule and exclusionRule. Population has eligibilityRule, device, market, segmentId and cohortId. Enrollment is a half-open from/to UTC interval. Metric definitions are one exact entry per decision metric: metricId, outcomeRule, nonSuccessRule, observationHorizonSeconds, businessDictionaryDigest, dictionaryVersion, sourceSystem and outcomeId. The latest outcome maturity boundary is enrollment end plus maximum horizon; capture must additionally allow ingestion lag. maxAgeSeconds must exceed horizon plus lag so there is a nonempty mature, fresh interval. Stopping has rule and plannedAnalyses (fixed-horizon/one is the initial supported method). Synthetic is explicit boolean and must match every source.

The cohortDigest binds the canonical object `{scope,assignment,population,enrollment}`. This documents the intended cohort; it does not prove actual membership. Input context must validate this binding before source parsing. Business outcomes such as payment settlement, accepted CRM lead or cancellation must be explicitly described by metric definitions, not inferred from event names.

Sources have exact sourceId, sourceKind (`experiment-aggregate-v1`), capturedAt, artifactText, artifactHash. At most 20 sources, <=2 MiB each and <=16 MiB total; strict duplicate keys, max depth/nodes and malformed Unicode/nonfinite values rejected. Source IDs unique; byte hashes verified before JSON interpretation. Fail on malformed/foreign input without returning a partial result. Original source content stays private.

Each raw JSON artifact has exact schemaVersion=1, scope, protocolDigest, cohortDigest, enrollment, synthetic, dataCompleteThrough, provenance, quality, assignmentCounts and metrics. Provenance: actor/locator/sourceSystem/queryDigest/method (export or manual). Quality: complete/sampled/thresholded/modeled tri-state flags and precision (exact/approximate/unknown). AssignmentCounts has controlAssigned/treatmentAssigned. Metrics are exact existing observation records with metricId/cohortDigest/control/treatment accounting. Missing metrics remain missing; extra or duplicate IDs fail. Do not trust source-authored review, grant or pass fields: these are not in the schema.

## Selection and chronology

Watermark cannot exceed capture; capture cannot exceed assessment or precede enrollment start. Enrollment may not be finished yet; retain an immature result rather than inventing completion. Report age is measured from enrollment end, not download time; a fresh download does not refresh old results. Eligibility requires complete, unsampled, unthresholded, unmodeled exact exports, mature watermark and capture with lag, nonexpired window, registration timestamp before enrollment start and supported fixed-horizon/one-analysis declaration. These are mechanical conditions, not proof of truthful declarations or absence of peeking.

Normalize every source and retain its reasons. Unknown original assignment counts make a source ineligible, even if its individual metric counts are present. Eligible sources with identical canonical assignmentCounts/metric content are aliases of one observation; normalize metric order before comparison. Distinct source IDs and reserialization must not inflate sample size. Conflicting eligible content blocks selection and retains every candidate; ineligible historic/manual artifacts remain visible without overriding eligible evidence. Never choose the most favorable source or merge arm counts across exports. No sources produces missing evidence, not a zero-sized experiment.

## Review boundary and output

This first ingestion step does not accept review booleans from any raw export. Mechanical facts can establish window/maturity only under attributed declarations. Semantic prerequisites such as valid randomization, no interference, independent registration history, eligibility, true cohort membership, complete metric family, definition correctness and quality review remain null until separately reviewed original evidence is bound to the exact context and source set. Therefore the initial adapter returns a blocked decision with precise review requests, even for otherwise complete supplied exports. This is an explicit staged implementation boundary, not final product behavior.

Output retains namespace, full context and digest, synthetic classification, normalized source records, exact source accounting, selected source IDs, selection reasons, evidenceSetDigest, internal decision and requests. The initial aggregate evidenceSetDigest binds sorted source IDs, kinds, capture timestamps and original byte hashes plus a stable bindingDigest. That bindingDigest covers scope, protocolDigest, maxAgeSeconds and ingestionLagSeconds, excluding assessmentAt. contextDigest still binds the full invocation clock. A later review must also bind all supporting artifacts, not merely this aggregate set. Deriving a digest is not authenticating the source. Request IDs bind the stable binding digest, owner and missing condition, while assessedAt remains lifecycle metadata; each request provides acceptable artifact/export metadata and fallback, never credentials. All declared metrics remain represented.

## Remaining review and workflow implementation

The next step adds a separately produced review artifact with reviewer attribution, reviewedAt/expiry, exact context/evidenceSet bindings, per-prerequisite verdict and source locators/reasons. Do not add a generic `reviewed=true` bypass. Replacing the protocol, adding a conflicting source, changing counts or reusing an expired review invalidates acceptance. Reviewer identity remains attributed unless a configured trust mechanism authenticates it. No review receipt can authorize site actions. The final workflow must integrate all data requests and observations into immutable JSON/MD/HTML, preserve prior refusals/history and satisfy host/pilot/commercial gates.

## Required tests before closure

Original byte substitution and duplicate keys; malformed Unicode/nonfinite/oversize; foreign scope/protocol/cohort; changed metric definition/horizon/margin; complete, missing and partial families; aliases/order invariance and contradictory exports; stale re-download/exact expiry; watermark/capture lag and enrollment still open; post-enrollment registration; manual/sampled/modeled/thresholded/unknown quality; synthetic mixing; forged source review/grant fields; no-source requests; no raw source-derived pass; complete reporting of both mechanical and independent-review blockers. Test scope remains broader than arithmetic and includes business outcome semantics in multi-profile fixtures.

## Independent design review resolutions and remaining boundary

The reviewer accepted aggregate-only ingestion with semantic review blocked, and required three changes before the review/workflow stage:

1. Supporting-artifact records must carry bounded verified original bytes, role, scope and hash. Original registration/configuration/query/cohort/dictionary evidence must enter the complete review evidence set, and every prerequisite verdict must name exact supporting hashes. Mutable locators and reasons alone are insufficient. This initial evaluator does not accept such verdicts; it leaves all those prerequisites unknown.
2. Metric definitions now bind sourceSystem, outcomeId and businessDictionaryDigest alongside free-text rules. The later supporting-artifact stage must validate the actual dictionary and query semantics against those identities; hash-shaped strings alone do not prove them.
3. Stable bindingDigest excludes the assessment clock. At review integration, independently enforce reviewedAt <= assessmentAt < expiry and reassess freshness/maturity each invocation. Changing protocol, evidence or policy invalidates review; merely advancing the clock does not change the stable evidence identity.

Exports with missing metrics are not merged. Source accounting retains every artifact and per-source reasons even where another complete export is selected. The evaluator currently returns a blocked internal decision and source-bound requests; packaging, actual reviews, multi-profile semantic validation and immutable report workflow remain open.

## Private supporting-evidence preparation

`prepareExperimentReview(context, aggregateSources, supportSources)` in `experiment-review-packet.mjs` first re-evaluates original aggregate sources, then verifies supplied supporting bytes. This stage cannot accept review verdicts or authorize output delivery. Its entire result is a private review packet, including raw support text; do not serialize it as a customer report.

Support envelopes have exact sourceId, scope, protocolDigest, synthetic, role, sourceSystem, metricIds, capturedAt, artifactText and artifactHash. At most 100 supports, each nonempty well-formed UTF-8 <= 1 MiB, with <=16 MiB total support bytes; aggregate limits remain separate. IDs are unique across both sets. Scope, protocol and synthetic state must match; timestamps must be valid and no later than assessment. All hashes verify original bytes before dictionary parsing. No locator is fetched and no imported query/instruction is executed.

Roles are registration-history, assignment-config, cohort-query, outcome-dictionary, metric-query, analysis-ledger, quality-evidence and interference-evidence. Global roles require empty metricIds; dictionary/query roles may name a subset of known unique metric IDs. Requirements cover each global role, each protocol metric dictionary and every supplied aggregate query, including ineligible/unselected aggregates. Merely naming a role is not semantic proof of the content.

Digest conventions are explicit: registration.artifactHash and aggregate provenance.queryDigest mean SHA-256 of original UTF-8 registration-history/query bytes in this adapter. businessDictionaryDigest means the existing enterprise canonical JSON digest of the complete parsed dictionary, not its original-byte hash. Each dictionary's original SHA-256 is also retained. The generic dictionary identity check requires a sourceSystem, version, and nonempty bounded outcomes array with unique outcomeId values. Additional definition fields are preserved as untrusted content, not normalized into business success. This supports original dictionaries without pretending they all use the business-observation event schema. Actual outcome semantics, query execution and cohort membership require independent review.

Dictionary requirements match metricId, sourceSystem, dictionaryVersion, outcomeId and canonical digest together. Query requirements match original hash/sourceSystem and cover every metric present in that specific aggregate. Registration matches its exact original hash. Requirements record all matching source IDs and distinct byte hashes; they do not select one competing artifact. An unmatched supplied artifact remains in the packet. Reused bytes across roles/IDs are listed as aliases, never additional independent corroboration.

Complete evidenceSetDigest binds schemaVersion 1, the stable aggregate evidenceSetDigest and every supplied supporting descriptor/hash in source-ID order. Each descriptor binds scope/protocol/synthetic, role, source system, sorted metric IDs, capture timestamp and original hash. Adding/changing unfavorable or unmatched support invalidates this identity. Ordering the inputs differently does not. Clock-only reassessment changes invocation metadata but preserves packet identity while freshness is re-evaluated. Requirement IDs include normalized expected support bindings, so a changed query hash/source/metric coverage is a different requirement. Missing-support request IDs bind stable scope/protocol/policy, requirement and owner, with assessment time separate.

Every requirement status is only binding-matched or missing-support. Semantic acceptance, reviewer authentication, provider authentication, causal acceptance and action authority remain false. A newly captured historical document is not proof of when registration happened; a fresh ledger export is not proof that all analyses were included. The subsequent receipt-verification stage must address those judgments against this exact complete packet.

## Attributed review receipt evaluator

`evaluateReviewedExperiment(context, aggregateSources, supportSources, policy, receipt)` rebuilds the packet from original bytes on every invocation. No cached packet or source-authored review flag is accepted. Policy has exact scope, reviewerIds (1–20 unique bounded IDs), allowedTypes (ai/human), positive maxAgeSeconds <= one year and validUntil. Scope must match. Policy is trusted caller configuration only in the sense of parameter ownership; an allowlisted string does not authenticate the person or host. Its canonical digest is bound by the receipt.

Receipt is null or exact artifactText/artifactHash, <=1 MiB original well-formed UTF-8 with verified SHA-256 and strict duplicate-key-aware parsing. Raw schema fields are schemaVersion=1, scope, protocolDigest, evidenceSetDigest, policyDigest, synthetic, reviewer, reviewedAt, validUntil, inventory and verdicts. Reviewer has id/type plus relationship (declared-independent/author/other/unknown), conflictOfInterest (none-declared/declared/unknown) and nonempty disclosure. Only declared-independent plus none-declared and a policy-listed ID/type can be accepted. This is attributed independence, never authenticated independence.

Review must follow every supplied capture and precede/equal assessment. Assessment is strictly before receipt expiry, policy expiry, reviewedAt + maxAgeSeconds and enrollment freshness expiry. Declared receipt expiry cannot exceed policy or source expiry. Return the effective earliest expiry explicitly. Scope/protocol/synthetic/policy/evidence changes invalidate old acceptance. Clock-only reassessment rechecks all current conditions while retaining stable identity.

Inventory lists every aggregate and support exactly once, including aliases, unselected and unmatched sources, with sourceId, original artifactHash, disposition and reason. Dispositions are supports/contradicts/unresolved/out-of-scope. Contradicts/unresolved block acceptance. Every mechanically selected aggregate alias must have a supports disposition before review acceptance can permit interpretation. Out-of-scope is reviewer-declared irrelevance, not proof of foreign scope; it never filters the original packet, aggregate selection, metric family or mechanical requirements. Missing/new inventory or changed hashes reject replay with explicit reasons. Duplicate entries are malformed input.

Exactly one verdict per each of the 12 review gates contains gate, verdict (accept/reject/pending), reason and up to 100 bindings. Each binding has requirementId, sourceId, artifactHash and locator `{lineStart,lineEnd}`. Lines are positive integers with start <= end and must exist in the original source text. Matching source IDs/hashes must satisfy the named packet requirement and have supports inventory disposition. Line bounds validate a locator, not the truth of its explanation.

Accepted gate coverage maps to complete requirements by role: design uses registration/assignment/cohort/ledger/dictionaries; preregistration uses registration; randomization uses assignment/cohort; interference uses interference/assignment; metric-family completeness uses registration/ledger/all dictionaries/all queries; one planned analysis uses ledger/registration; source scope uses all requirements; population completeness uses cohort/quality/all queries; maturity uses dictionaries/queries/quality; fixed horizon uses ledger/registration; metric definitions use all dictionaries/queries; quality uses quality/assignment/cohort/queries. Unknown, duplicate or omitted gates are invalid. Pending/rejected gates or omitted matching evidence block acceptance. Aliases add no independent evidentiary weight.

An accepted-attributed-review may supply semantic facts to the existing decision predicate, but mechanical maturity/fixed-horizon facts are ANDed with recomputed source eligibility. Source selection and original counts are never replaced. Thus an accepted receipt can coexist with a blocked decision for conflicting/immature/stale/ineligible exports. Return both statuses without conflation. Criteria support means supported under supplied review, not authenticated causality or rollout permission. Reviewer/provider/independence authentication, causal acceptance and action authority remain false.

The return includes the private pre-review packet and raw receipt, the final decision, attributed policy and review status/reasons/effective expiry. Use the top-level decision/requests for subsequent workflow; packet retains the prior unreviewed view for evidence history. Resolved semantic-review requests are removed from the current request projection after acceptance, while mechanical blockers remain. Receipt errors generate scoped exact-packet/policy requests with stable identity and assessedAt separate. Immutable report projection, actual reviewer-host evidence and commercial gates remain outstanding.
