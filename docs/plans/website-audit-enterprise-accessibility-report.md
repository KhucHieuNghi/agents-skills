# Accessibility canonical report integration contract

Development implementation of task3 in the [accessibility plan](website-audit-enterprise-accessibility.md). Not commercial acceptance. Keep 0.3.12 immutable while implementing.

API evaluateEnterpriseAccessibility(sourceDirectory,bundle,newDirectory) forks the existing P2 source run. Bundle is sourceDigest/newRunId/assessmentAt/evaluations. Each entry is evaluationId, kind axe|scenario, window {from,to}, context excluding customerId/assessmentAt, sources. The window is an explicit completed half-open UTC observation window, from < to <= assessmentAt; axe timestamps and all scenario attachment/step timestamps must lie within it. Context uses the existing strict normalizer schema. No host authority, imported verdict or supplied normalized row is accepted. At most50 entries,16MiB new raw bytes; persisted run <=32MiB.

Same evaluationId retains kind/context population/window identity; maxAgeSeconds may change as an explicit policy revision. Canonicalize expectedRuleIds and requiredSteps/ruleIds ordering. Population identity excludes obligation lists, so different IDs cannot split or overlap obligations for the same target/state/device/protocol/window population; consolidate those into one evaluation. Changing the obligation set under an existing ID requires an explicitly revised scope rather than silent deletion. Duplicate population under another ID rejects. Rebuild all retained evaluations from raw bytes on every import, including untouched entries. Full manual coverage stays an explicit unknown check. Axe rows map to accessibility; scenario rows with WCAG references map to accessibility and product diagnostics map to ux-cro. Required modules/entities must already be in source scope.

Check scenario identity binds namespace, exact entry population, rule and step identity; windowId hashes the declared window. Policy hashes bind source evaluator fingerprint/context. Separate row evidence carries the exact recomputed row, supporting expiry and source IDs. For axe, expiry is from current eligible records supporting the outcome; for scenario it is from the selected nonconflicted resolutions and their used facts. Unknown evidence expires at assessment if no eligible support exists. No automatic conformance or human review claim.

Persisted indexes are lookup hints only: reproject each indexed base evidence entry at its original assessment before trusting ownership. Compare complete cached row content/digest/expiry and check identity/dependencies/policies; only already-invalidated unknown core verdicts may differ from original verdict. Reject orphan indexes, missing indexes for owned checks, scope rebinds, duplicate indexes, rehashed forged rows and foreign request/check ownership before creating output. Every evaluationId retained in base evidence must have an active validated index even if both its index and checks were deleted. The active index must point to the latest assessment/lineage evidence for that ID; a rollback pointer to a self-consistent old row is rejected. Deletion IDs come from recomputed owned checks/requests, not supplied arrays. Historical evidence is append-only and parent immutable. New source/expiry/policy changes archive prior check verdicts through P2 reconciliation.

Failed scoped checks produce draft low-confidence findings, never authenticated or independent acceptance. Human/AI source attribution is not a report review decision. Public projection must omit raw source payloads, HTML/selectors, attachment text, author notes and environment strings. Numeric observation is only the count of semantic supplied records/traces in the declared historical window, not a quality score or execution count. Parent observations remain immutable; new revisions append separately bound historical snapshots. Preserve valid findings/actions from other modules explicitly and obtain fresh target-bound review decisions.

Unknown requests preserve declined responses and name target/state/viewport/window, required source format/facts, owner, least privilege and fallback. Preserve all intake and unrelated module checks. Data requests for module coverage remain even when every supplied rule reports pass.

Tests: canonicalJSON/Markdown/HTML; axe+scenario namespaces and product diagnostics; unvisited/manual gaps; source raw exclusion; exact expiry; stable check identity within same window; different windows/devices/state; independent fresh review timestamps; declined requests; untouched re-evaluation; forged cache/index/foreign ownership rejection before output; immutable parent/report observations. Exercise actual native axe and scenario fixtures before package freeze. Source runtime and full enterprise acceptance remain separate gates.
