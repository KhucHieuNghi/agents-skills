Hướng dẫn cho thành viên team

Skills được cài như thế nào?

Mục tiêu là để mọi người chọn đúng capability đã được team kiểm tra, thay vì tự tìm và cài một skill bất kỳ từ bên ngoài.

1. Mục tiêu

Một skill là hướng dẫn chuyên biệt cho coding agent: ví dụ viết UI, review accessibility, tạo tài liệu, hoặc làm việc với một công nghệ cụ thể. Project này là cổng cài đặt được curate cho các skill đó.

Repo public này có thể chứa skill generic của chính nó, đồng thời catalog các skill public từ nguồn upstream đã được kiểm tra.

2. Luồng hoạt động

BƯỚC 1

Nguồn skill

Skill do team viết hoặc một skill public đáng tham khảo.

BƯỚC 2

Catalog public

Repo ghi Git URL canonical, use case và giới hạn của skill.

BƯỚC 3

Catalog đã duyệt

Catalog ghi rõ skill nào phù hợp, không phù hợp và có xung đột.

BƯỚC 4

Người dùng chọn

CLI so sánh các lựa chọn; người dùng chọn profile rồi mới cài.

skills.sh là nơi khám phá. Catalog ghi chính xác Git URL public mà CLI sẽ stage, validate và cài vào project.

4. Người dùng chọn gì?

Người dùng nói nhu cầu của mình, ví dụ landing-page, redesign hoặc documentation. Lệnh recommend hiện bảng so sánh các profile phù hợp.

  1. Đọc mục “Why choose it”, “Suitable for” và “Avoid”.
  2. Chọn một profile, không cài nhiều style authority cùng lúc.
  3. Chạy apply-profile với tên profile đã chọn.

3. Team tổ chức skills như thế nào?

User không cần nhớ URL nguồn hay tự đánh giá từng skill. Team quản lý ba lớp bên dưới; chỉ catalog đã duyệt được dùng để recommendation và install.

Lớp Chứa gì? Ai thay đổi?
Source public Skill bundled trong repo hoặc upstream open source Người phụ trách kỹ thuật
./catalog.yaml Profile, use case, mô tả phù hợp, xung đột và foundation Người phụ trách catalog
Project của user Skills đã được cài cho agent của project đó User, thông qua CLI

Catalog là “menu đã duyệt”, không phải nơi chứa nội dung skill. Nó được commit ở root repo public này. User clone/pull repo sẽ có cùng catalog và không cần GitHub private hoặc đường dẫn bí mật.

5. Ví dụ sử dụng CLI

Chạy lệnh từ root của repository này. CLI tự dùng file ./catalog.yaml; chỉ dùng --catalog khi cần thử một catalog public khác.

Bước A — xem các lựa chọn

agent-skills recommend --intent landing-page

CLI hiện bảng profile. User đọc lý do, phạm vi phù hợp, giới hạn, skills đi kèm và Design foundation (nếu có).

Bước B — nếu chọn Design foundation

npx getdesign@latest add <slug-da-duoc-team-duyet>

Đây là bước thủ công. User xem file DESIGN.md vừa tạo trước khi tiếp tục; CLI không tự tải hoặc ghi đè file này.

Bước C — cài đúng profile đã chọn

agent-skills apply-profile <profile-da-chon> \
  --target codex,claude-code,opencode \
  --scope project

CLI stage và validate toàn bộ skills trước khi gọi installer. Nếu một skill invalid hoặc có xung đột, CLI dừng trước khi cài.

6. Skill public được cập nhật ra sao?

Việc Ai làm Kết quả
Theo dõi bản mới từ nguồn public Người phụ trách hoặc automation Có đề xuất thay revision hoặc URL trong catalog
Review thay đổi, test và kiểm tra license Team kỹ thuật Một revision được duyệt
Cập nhật catalog Người phụ trách catalog User pull repo và thấy catalog đã được review

7. Ví dụ: làm landing page

Recommendation có thể đưa ra hai profile: một profile thiên về layout/motion, một profile thiên về cấu trúc và brand consistency. Người dùng đọc bảng, chọn một profile phù hợp với mục tiêu trang, rồi cài profile đó.

Nếu profile có “Design foundation”, người dùng có thể chọn tạo DESIGN.md trước. Đây là mô tả màu sắc, typography, spacing và component để các UI sau giữ cùng một ngôn ngữ thiết kế.

Quy tắc ngắn gọn: chọn foundation nếu cần, chọn một profile style, sau đó mới cài. Khi không chắc, hỏi người phụ trách design system thay vì cài tất cả.
