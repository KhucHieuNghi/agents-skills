Catalog Development Reference

This page covers the generic skill catalog and authoring patterns. For the versioned Upstream and Solution Skill product, use the product model and technical V1 release guide.

Overview

The Agent Skills system teaches AI coding agents how to perform complex tasks through portable instruction packages called skills.

Supported agents: Claude Code and Codex.

Three rules govern the system:

  1. Execution — How a skill runs (inline vs. subagent)
  2. Bundling — How skills are stored, combined, and share state
  3. Installation — How to install and update skills in a target project

Skill Sources

Skills come from exactly two sources:

  • Bundled Self-authored in skills/ directory of this repo
  • External Third-party from public Git repositories
Aspect Bundled External
Location skills/<name>/ in this repo Separate Git repository
Ownership You maintain it Upstream maintainer
Validation Immediate (--source skills) After pull stages the source
Updates Your commits git pull from upstream
Integration Full (shared state, cross-refs) Through profiles only
CI coverage Tested in this repo's CI Validated at install time only
When to choose bundled: You own it, it's team-specific, needs tight integration with other skills.
When to choose external: Maintained by others, general-purpose, want upstream updates without forking.
Rule 1: How a Skill Executes

Activation

A skill activates via the $skill-name syntax:

Use $codebase-onboarding-c4 to onboard me to this project.

The agent reads SKILL.md, loads contracts from references/, and executes.

Root-owns-everything: The root agent always owns user interaction, approval gates, evidence registry, routing decisions, reconciliation, quality gates, and every write.

Inline vs. Delegate

Stay Inline Delegate to Subagent
Single question or sequential chain 2+ independent tracks exist
Shared-model work Each track is bounded with clear output
User interaction or approval Tracks are strictly read-only
Reconciliation of findings Parallel execution has real benefit
Quality gate evaluation —
Any write operation —
Subagent constraints: Cannot expand scope, request access, edit code, mutate state, write documents, or talk to the user. Returns findings only.

Fallback: If delegation unavailable, execute the same tracks inline. Contracts don't change — only topology changes.

Quality Gates

Result Meaning
PASS All required gates pass
PASS_WITH_GREY_ZONES Usable but optional evidence unavailable
NOT_READY Foundational evidence unreliable

Five gates evaluated independently: Product Journey, Technical C4, Engineering Navigation, Evidence Integrity, Security/Public Boundary.

Failed section: one targeted retry (Standard). Deep mode: +1 reviewer track. Never retry entire investigation.

Rule 2: How Skills Are Bundled

Package Structure

my-skill/
  SKILL.md              # REQUIRED — Frontmatter + instructions
  references/           # Contract documents (agent reads these)
  assets/               # Templates, CSS, static files
  scripts/              # Verification scripts (Node ESM .mjs)
  agents/               # Per-target interface configs (YAML)

SKILL.md Frontmatter

---
name: my-skill          # Must match directory name exactly
description: Use when...  # Non-empty
---

Validation fails on: name mismatch, empty description, missing frontmatter.

Agent Interface (agents/*.yaml)

interface:
  display_name: "My Skill"
  short_description: "One-line description."
  default_prompt: "Use $my-skill to [action]."

Create one file per target: claude-code.yaml and openai.yaml.

Catalog & Profiles

catalog.yaml

version: 1
sources:
  bundled:
    reference: skills
  hallmark-upstream:
    reference: https://github.com/nutlope/hallmark.git

skills:
  my-skill:
    source: bundled
    tags: [tag1, tag2]
    summary: One-line summary.
    suitableFor: [intent-a]
    notSuitableFor: [intent-b]

profiles:
  my-profile:
    intents: [intent-a]
    skills: [skill-a, skill-b]  # Order matters!
    summary: What this achieves.
Profile Skills Purpose
documentation html-docs-standard, hallmark Engineer docs + optional polish
codebase-onboarding codebase-onboarding-c4, html-docs-standard, hallmark Full codebase investigation
hallmark-landing hallmark Landing pages, redesigns
Rules: First skill = primary authority. All skills must exist in catalog. Profiles fail on undefined/conflicting skills. Bundled + external can mix.

Multi-Skill Interaction

  1. Shared paths — .onboarding/ (state/evidence), docs/onboarding/ (output)
  2. Explicit delegation — SKILL.md references another skill by name
  3. Shared brand state — .onboarding/brand/DESIGN.md
  4. Authority chain — First skill is primary; downstream must preserve rules and pass verifiers

State & Resume

# .onboarding/state.yaml
schema_version: 1
run_id: ""
mode: standard
status: preflight
resume_from: preflight
  • Git HEAD or fingerprint changes → mark affected evidence stale
  • Rerun only impacted tracks, never entire workflow
  • YAML writes use atomic temp-file-then-rename

Brand Profile Workflow

ensure-brand-profile.mjs → { action: "reuse" | "first-use" | "invalid" | "refresh" }
  • reuse → Use existing profile silently, no questions, no network
  • first-use → Ask Brand name + Brand website, extract, apply
  • invalid → Same as first-use
  • refresh → User explicitly requested re-extraction

Apply writes DESIGN.md + generates docs-brand.css + verifies in one atomic step. Stored at .onboarding/brand/DESIGN.md (locally ignored, never committed).

Rule 3: Installation & Versioning

Install Commands

Direct installation (from any source)

npx --yes skills add <source-path-or-git-url> \
  --skill <skill-name> \
  --agent codex --agent claude-code \
  --yes

From GitHub (public users)

npx --yes skills add \
  https://github.com/KhucHieuNghi/agents-skills.git \
  --skill codebase-onboarding-c4 \
  --agent codex --agent claude-code --yes

Profile install (from CLI checkout)

npm run dev -- apply-profile codebase-onboarding \
  --target codex,claude-code --scope project

Installed File Layout

target-project/
├── .agents/skills/
│   ├── codebase-onboarding-c4/
│   │   ├── SKILL.md
│   │   ├── references/
│   │   ├── assets/
│   │   └── scripts/
│   ├── html-docs-standard/
│   └── hallmark/
├── skills-lock.json
└── ... (project source)
Agent Target ID Project Marker
Claude Code claude-code .claude/
Codex codex .codex/
No-overwrite policy: Existing skills never overwritten implicitly. Remove old version first, then re-install.

Versioning & Updates

skills-lock.json records installed skills, source URL, and commit hash.

Detecting updates

# Compare installed vs source
diff .agents/skills/codebase-onboarding-c4/SKILL.md \
  /path/to/agents-skills/skills/codebase-onboarding-c4/SKILL.md

# Check recent changes
git log --oneline --since="2 weeks ago" -- skills/

Update workflow

  1. Pull latest source: git pull
  2. Validate: npm run dev -- validate <skill> --source skills
  3. Remove old: rm -rf .agents/skills/<skill-name>
  4. Re-install from updated source

Resume after update

  • Check schema_version compatibility
  • Compatible: mark changed contracts as stale, rerun affected tracks
  • Incompatible: warn and suggest fresh run
Creating New Skills

Path A: Bundled Skill (Self-Authored)

  1. Choose lowercase-hyphenated name (no catalog conflicts)
  2. Create structure: mkdir -p skills/<name>/{references,assets,scripts,agents}
  3. Write SKILL.md with frontmatter (name + description)
  4. Write contracts in references/ (one concern per file, <200 lines, imperative)
  5. Add templates in assets/
  6. Add scripts in scripts/ (Node ESM, exit 0/1, PROJECT_ROOT arg)
  7. Add agents/{claude-code,openai}.yaml
  8. Register in catalog.yaml with tags, summary, suitability
  9. Validate: npm run dev -- validate <name> --source skills
  10. Run checks: npm run format:check && npm run lint && npm run typecheck && npm test

Path B: External Skill (Third-Party)

  1. Identify external Git URL with valid SKILL.md package
  2. Add source to catalog.yaml: 
    sources:
  my-external:
    reference: https://github.com/org/repo.git
  3. Register skill with source: my-external
  4. Validate: npm run dev -- pull <url> then validate
  5. Optionally add to a profile
External constraints: You don't control evolution. Same validation rules apply. Pin to branch/tag for stability.

Bundle with Existing Skill

To make your new skill use html-docs-standard for HTML output:

  1. In SKILL.md: Use html-docs-standard for branded HTML rendering
  2. Define shared output paths
  3. Create profile with your skill first (primary authority): 
    profiles:
  my-analysis:
    intents: [analysis]
    skills: [my-skill, html-docs-standard]
    summary: Analysis with branded HTML output.

Your skill is design authority; downstream skills handle presentation only.

  --agent codex --agent claude-code --yes

Invocation Prompt

Use $codebase-onboarding-c4 to onboard me to this project.

Run in Standard mode.
Select one primary business operation journey with a Journey ID.
Begin inline; use subagents only for independent read-only tracks.
Return findings in chat first. Ask before writing files.
Continue code-only when evidence unavailable; mark grey zones.
End with quality-gate result and Ready to implement assessment.
Mode Scope When
Quick Surface-level, one flow Small repo, clear task
Standard Complete C1/C2 + selective C3 Default for onboarding
Deep Multi-domain, additional reviewer Complex systems

8 Workflow Stages

# Stage What happens
1 Preflight Verify tools, index, topology, output paths
2 Orientation Actors, boundaries, containers, runtimes, stores
3 Journey selection Choose one business journey, assign Journey ID
4 Gap planning Compare evidence vs. required contracts
5 Investigation Inline or delegate independent read-only tracks
6 Reconciliation Deduplicate, resolve contradictions, normalize
7 Quality gates Evaluate 5 gates, targeted retry on failure
8 Delivery Chat report first, write artifacts after approval

.onboarding/
├── brand/DESIGN.md

Both roots must be locally ignored (.git/info/exclude). Markdown is source of truth; HTML is refreshed readable view.

Evidence labels: verified-from-source (confirmed from code), inferred-from-source (logical inference), needs-confirmation (cannot verify from code alone).
Using AI Agents

Develop Skills with AI

Open this repository in Claude Code or Codex. The agent reads AGENTS.md and can scaffold skills.

Create a new skill

I want to create a new skill called `api-documentation` that:
- Reads OpenAPI specs from the project
- Generates engineer-facing API docs
- Uses html-docs-standard for HTML rendering
- Bundles in a profile called `api-docs`

Follow AGENTS.md Path A. Create structure, SKILL.md, contracts,
agent configs. Register in catalog.yaml. Validate when done.

Install skills into a project

Install the codebase-onboarding profile into this project.
Use the GitHub source URL.
Verify all files exist after installation.
