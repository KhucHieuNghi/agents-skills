Adaptive Codebase Onboarding

Cách giúp engineer hiểu Product/Business, Technical C4 và Operability trước khi nhận một bounded implementation task.

1. Trạng thái capability

Current capability

Skill hiện tại điều tra codebase bằng CodeGraph và RTK, tạo mô hình Product/Business và C4 dựa trên evidence.

Current execution routing

Skill bắt đầu inline, chỉ giao bounded read-only track độc lập cho subagent, sau đó root reconcile evidence và đánh giá task-scoped readiness.

Target adaptive workflow

Local .onboarding/ YAML state, automatic resume và Markdown-to-HTML renderer chưa được triển khai; template và verifier hiện có chưa phải renderer hoàn chỉnh.

Không dựa vào target behavior cho automation production trước khi implementation và acceptance tests tương ứng đã hoàn tất.

2. Cài skill vào project thật

Chạy installer từ root của target project. Dùng direct installer cho cross-project installation; apply-profile hiện phù hợp khi vận hành bundled CLI từ chính checkout này.

Bước 1 — khai báo hai absolute path

skills_source=/absolute/path/to/agents-skills
target_project=/absolute/path/to/project

Bước 2 — validate source package

cd "$skills_source"
npm install
npm run dev -- validate codebase-onboarding-c4 --source skills

Bước 3 — kiểm tra target trước khi thay đổi

cd "$target_project"
pwd
git status --short --branch
test -f AGENTS.md && sed -n '1,220p' AGENTS.md

Bước 4 — cài onboarding skill

npx --yes skills add "$skills_source" \
  --skill codebase-onboarding-c4 \
  --agent codex \
  --yes

Bước 5 — cài HTML standard nếu cần durable docs

npx --yes skills add "$skills_source" \
  --skill html-docs-standard \
  --agent codex \
  --yes

Bước 6 — xác nhận package đã cài

test -f .agents/skills/codebase-onboarding-c4/SKILL.md
test -f .agents/skills/codebase-onboarding-c4/references/real-project-usage.md
test -f skills-lock.json
git status --short

Luôn review các file mới. Không overwrite skill đang tồn tại và không tự động stage hoặc commit.

3. Preflight trong target project

Bước 7 — kiểm tra prerequisite read-only

cd "$target_project"
codegraph --version
rtk --version
git status --short

Nếu thiếu tool, dừng và dùng official installation instruction. Agent không được tự cài global tool hoặc đổi agent config.

Bước 8 — xử lý khi chưa có index

Xác nhận chính xác index root, sau đó hỏi project owner trước khi chạy codegraph init. Với multi-repo, root có thể là parent workspace thay vì một repository con. 

CodeGraph chưa có valid index tại <target root>.
Tôi có thể chạy `codegraph init` tại chính xác root này không?
Operation chỉ tạo local index state và không sửa application source.
cd "$target_project"
codegraph init
codegraph status

4. Khởi chạy onboarding task

Bước 9 — mở Codex tại target root

Mở task mới để runtime discover skill vừa cài, rồi dùng prompt Standard sau: 

Use $codebase-onboarding-c4 to onboard me to this project.

Outcomes:
1. Understand the Product/Business context and primary business flow.
2. Understand C1, C2, selective C3, runtime, data, auth, and tests.
3. Be Ready to implement: <bounded first task>.

Run in Standard mode. Begin inline to establish one shared system map.
Use subagents only for independent, read-only investigation tracks.
Return findings in chat first. Do not create or replace files without asking.
Label every material conclusion with its evidence status.
If external evidence is unavailable, continue code-only and mark a grey zone.
Mode Phạm vi Khi chọn
Quick Orientation, primary flow, một change path và blocker Repo nhỏ hoặc cần bắt đầu một task rõ ràng
Standard Ba onboarding layer và một readiness assessment Mặc định cho engineer mới
Deep Multi-domain/runtime, data, queue và failure modes Senior engineer hoặc hệ thống phức tạp

7. Adaptive execution

Mode Khi dùng Ownership
Inline Một bounded, sequential investigation track Root điều tra và tổng hợp
Subagent Ít nhất hai track độc lập và runtime hỗ trợ Subagent chỉ trả structured findings
Fallback Multi-agent unavailable hoặc task thất bại Root chạy cùng contract inline

Root luôn sở hữu user interaction, approval, evidence reconciliation, readiness và artifact writes.

8. External access policy

Bước 10 — trình bày access plan trước khi truy cập

  1. Nêu connector/source và purpose.
  2. Nêu bounded scope và read-only operation.
  3. Nêu configuration name nhưng không nêu value.
  4. Nêu evidence mong đợi và conclusion nào có thể thay đổi.
  5. Chờ user cấu hình credential bên ngoài conversation.
  6. Chỉ truy cập sau explicit approval.
  7. Thiếu access thì tiếp tục code-only và ghi grey zone.
Source: <MCP, document system, or database>
Purpose: <question this evidence answers>
Scope: <bounded read-only operation>
Configuration: <names only, no values>
Expected evidence: <facts to confirm or contradict>

Please configure access outside this conversation and explicitly approve
before I use the connector.

Database mặc định schema/metadata first, bounded read-only query, no mutation và không lưu raw personal hoặc customer data. Không paste credential vào chat, command, log hoặc artifact.

9. Review và durable artifacts

Bước 11 — review chat report trước

Report phải bao phủ Product/Business, Technical C4, Operability, evidence status, contradictions, grey zones và first-task change map. Chỉ yêu cầu tạo file sau khi nội dung đã được review. 

Create the durable onboarding documents now.
Check whether target files exist and ask before replacing them.
Use $html-docs-standard, Mermaid, local assets, and evidence labels.
Do not include credentials, private URLs, customer data, or unsupported claims.

10. Ready to implement

Bước 12 — assessment cho một bounded task

Assess whether I am Ready to implement <bounded task>.
Return Ready, Ready with constraints, or Not ready.
Support the verdict with source paths, CodeGraph call paths, tests,
unresolved grey zones, and one next action for every blocker.

Một verdict hợp lệ phải xác định:

  • File, symbol, route và call path dự kiến thay đổi.
  • Upstream/downstream dependency và impact boundary.
  • Test cùng local verification command cần chạy.
  • Data, auth, migration, queue hoặc deployment impact.
  • Grey zone còn lại và risk đối với đúng task đó.
  • Safest first implementation sequence.

Resume trong cùng task bằng completion report gần nhất. Khi mở task mới, cung cấp sanitized report hoặc approved docs, rồi revalidate Git và CodeGraph state trước khi dùng kết luận cũ.

11. Troubleshooting

Triệu chứng Nguyên nhân thường gặp Safe next action
Codex không discover skill Sai target root hoặc task mở trước khi install Kiểm tra .agents/skills/codebase-onboarding-c4/SKILL.md, rồi mở task mới tại đúng root.
Installer muốn replace package Skill đã tồn tại Dừng, review version và lockfile trước khi update.
CodeGraph không có valid index Sai root hoặc chưa init Xác nhận root và hỏi trước khi chạy init.
Product intent không rõ Code không phải approved product specification Giữ conclusion ở mức inferred và tạo grey zone.
MCP/database unavailable Thiếu connector, permission hoặc external config Tiếp tục code-only; ghi impact, owner và verify path.
Kết luận cũ có thể stale Branch, dependency hoặc index đã thay đổi Recheck Git và CodeGraph, rồi revalidate evidence.

Xem command, single-repo/multi-repo example và checklist đầy đủ tại real-project usage runbook.

Phase Deliverable Gate

Khi phát triển hoặc kiểm tra bundled CLI ngay trong repository này, dùng profile command sau. Đây không phải cross-project install command:
