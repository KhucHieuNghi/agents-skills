# Development provider inventory projection

The registered enterprise assembler now accepts replay-validated provider imports and deliberately planned provider-only runs. This is development code, outside the candidate package; solution version remains 0.3.26.

## Behavior

Every retained provider import is replayed from its original supplied object before projection. Exact complete-input digests group aliases; repeat imports are not independent observations. Distinct fresh inputs remain competing regardless of import order or the request pointing at the latest import. A single fresh input group is only an attributed candidate when the provided request references that group. It is not provider-authenticated, semantically eligible or accepted assessment evidence.

Declined and invalid dispositions suppress candidates. Expired imports remain historical; fresh competitors remain current capture-age records. Pending targets expose canonical unknown checks and actionable data requests. They do not get fabricated evidence or an evidence-free narrative: the first focused run caught that report invariant, which remains intact.

Customer output contains inventory counts, evidence references and fixed resolution instructions. Original payloads, locators, configuration bodies and dimensions are excluded. Numerical metrics, detailed normalized limitation projection, explicit source-resolution decisions and semantic assessment remain open; this checkpoint does not turn inventory counts into provider measurements. Candidate selection descriptors are development outputs, not a new canonical schema field.
