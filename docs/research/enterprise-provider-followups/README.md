# Provider follow-up obligations — development prerequisite

`planProviderFollowups` derives an in-memory private plan from the provider owner's replay-validated source inventory. It produces separate proposed canonical-request-shaped obligations for incomplete pages/configuration, timezone/currency metadata, quality interpretation and conflicting fresh inputs. Business outcome sources use their own normalized gap location; partial capture, empty exports, manual assertions and missing provenance have fixed, specific guidance. Unknown gap codes become generic owner-review obligations without copying source text.

Each obligation is bound privately to the target and the exact source evidence IDs/digests. Repeated identical imports do not multiply logical gap obligations; a competing-input obligation binds the complete fresh source set. Requested status is an unfulfilled proposal, not a verified result. Declined or invalid primary sources are not reopened by this planner. Original payloads, locators and free-text source descriptions are not copied into the plan.

This is **not yet a persisted request lifecycle or customer report integration**. It does not preserve an old obligation when its source expires or its gap disappears, record a separate follow-up refusal, fulfill a request, validate a host review, resolve competing inputs or authorize disclosure. It must not be added directly to a run: the provider owner currently rejects unindexed follow-up requests and canonical evidence matching requires a dedicated replayable resolution artifact. Follow-up implementation must retain obligations across revisions and bind any fulfillment to a complete source set, independent decision and expiry; the existing parent report and declined/reopen rules remain mandatory.

Independent review found and verified the fix for missing business-owner gaps and unknown-code fallback. Synthetic tests cover incomplete GA4 configuration, aliases, competing sources, refusal and business partial/empty/manual/provenance gaps. These are prerequisite tests, not proof of enterprise completion or source-owner acceptance.
