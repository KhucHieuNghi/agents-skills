# Runtime and journey report assembly

This development checkpoint adds `projectStoredRuntime(run)` and `buildStoredEnterpriseReport(sourceDirectory, metadata, outputDirectory)` under `scripts/`. It integrates the three journey workflows with tracking/consent runtime evidence. Other enterprise modules remain unregistered and reject explicitly; this is not the completed all-module assembler.

## Evidence and projection contract

Runtime projection first calls the packaged original-source inspector from candidate 0.3.25, which validates the entire retained parent/derived evidence graph and ownership. Every active runtime evaluation must match the final run assessment time. A later clock requires an explicit reassessment revision; rendering never advances time or revives a previous finding.

Candidate findings come only from replay-derived records whose actual current check is still fail. Historical projections contain source-envelope counts and fixed assessment-history text, not revived findings or a claim about current website state. Source counts are labeled as envelopes, not independent executions, conversions or complete coverage. Supplied synthetic/real-declared classification remains explicit. No raw source payload, locator, policy owner prose or participant identity is copied into these projections.

The assembler always invokes all registered module projectors; metadata cannot contain caller-selected findings or projections. It accounts for runtime parent and derived rows through the runtime owner rather than treating each artifactType match as a separate evaluation. Unsupported evidence rejects instead of disappearing. Canonical output preserves selected-module checks, requests, history and scope through the existing report model. Findings are unreviewed candidates, not accepted commercial conclusions.

Source digest is checked before projection and reread before saving. This is optimistic consistency only. The entrypoint creates an initial report and does not implement report-parent review/action preservation, research disclosure rights, locking or delivery authority. Those remain required by the full assembly plan. The earlier journey-only entrypoint retains its narrower contract.

## Verification and review

Five new tests cover canonical runtime output/privacy, stale-clock refusal with no output, fresh assessment of expired sources with historical observations and no current findings, caller projection/unsupported evidence rejection, and mixed task+tracking+consent assembly. The mixed case advances the clock through task evaluation, then explicitly reassesses runtime at that clock; both module families appear alongside historical runtime text. Original source-run digests remain unchanged.

The independent reviewer ran 24 tests across runtime workflow, stored runtime reporting and journey composition; all passed, with no material issue identified in the scoped source review. It did not run the full repository suite or browser harness.

The reusable offline harness `tests/browser/enterprise-stored-report.mjs` loads a validated canonical report and checks customer/public editions at widths 390 and 1440. It verifies exact narrative DOM parity, privacy canaries, no scripts/external HTTP requests/page errors, no horizontal overflow and keyboard skip navigation. Local receipts/screenshots are retained in `build/enterprise-runtime-assembly-browser-final/`. These checks are mechanical, not accessibility conformance or general usability acceptance.

The first harness attempt assumed public reports contain a narrative array. Public projection intentionally omits that field. The harness was corrected to use an empty expected array for the public edition and rerun in a fresh output directory; the earlier outputs remain retained. No product code was changed for that harness correction.
