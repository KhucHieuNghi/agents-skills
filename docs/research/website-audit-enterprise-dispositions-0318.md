## Implemented lifecycle

Replay-proven superseded measurement checks may receive independently attributed replacement review, applied into a new immutable run. Declared checks/history remain present, replacement pass/fail/unknown stays real, and durable per-target requests replace only the reviewed portion of a grouped migration request. Expiry, context changes, reassessment and explicit revocation invalidate the decision. Reintroduced obligations keep fresh real results; a subsequent disappearance remains readable. Final ownership replay runs before saving.

Renewal requires a new proposal/review for the current source and a separate explicit host-review receipt. The ordered proof chain preserves old evidence, revocations and denied content hashes. Old receipts cannot become fresh merely by renaming them or dropping chain entries. Existing active N/A cannot be renewed without first becoming unresolved. The chain is bounded to 100 prior proofs per target.

The installed CLI exposes propose/review/apply/renew/revoke. The separate HOST-REVIEW.json is caller-attested host provenance, not cryptographic proof of independence. The host must observe genuine separate review; merely filling reviewer/provenance strings is insufficient. Helper outputs retain false reviewer-authentication and commercial-acceptance flags.
