This checkpoint implements the descriptive-funnel portion of journey plan step 5. Source remains development-only in `scripts/enterprise-journeys/workflow.mjs`; candidate 0.3.24 and its immutable archive are unchanged. Functional journey observations, research, experiment interpretation, browser execution, native-host trials and full enterprise acceptance remain open.

The new workflow binds input to the parent run digest, derives customer/time from the run, preserves original source artifacts, enforces evaluation scope identity and replays untouched evaluations at the new assessment time. Historical and active observations are recomputed from strict original source bytes. JSON report values retain numerator/denominator, Markdown/HTML are generated by the existing renderer, raw export payloads are excluded from report projections, and synthetic classification remains visible. Arithmetic never produces a UX pass or a causal finding.

Independent source review by `enterprise_contract_review` identified two material defects:

1. An unchanged replay recreated an invalid request as requested and erased its diagnostic reason; provided bindings were similarly lost. The invalid-response regression failed before the correction. The workflow now preserves lifecycle/evidence/invalidation metadata, with additional tests for provided and expired evidence.
2. Historical observations accepted an evidence record whose source, ID and window did not match its inner funnel payload. The forged-history regression failed before the correction. A shared replay validator now checks content shape, evaluator version, derived ID, source/type, entity/scope/window, customer/lineage, observation time and expiry for both active and historical records.

The reviewer also confirmed the earlier endpoint-binding correction and the descriptive/unknown/stale behavior. Fixes are covered by author-run regressions; no independent re-review of those fixes is claimed.

Implementation ruling: retain one stable combined evidence-and-research request per transition rather than silently changing a measurement request into a research request. Its formats and obligation remain stable whether counts are available or missing; supplemental instructions identify the precise gap. This avoids losing prior responses, but separate research-only and aggregate-only response lifecycles remain a usability limitation until the research adapter is implemented. Provided evidence never changes the unknown UX check.
