## Corrections and behavior

Indexes now retain up to 100 historical base IDs. Each base and generated row is regenerated, compared exactly and checked against supported evaluator fingerprint, lineage, chronology and invariant population scope. Unowned canonical base/check evidence and missing history reject. Existing revisionRunId is retained in content identity, so each activation remains a distinct occurrence. No separate content-reuse convention was introduced.

Request windows use stable serialization, and evaluation ordering uses code-unit comparison. This fixes the input-order defect where a valid window supplied as to/from produced different export instructions after canonical save/load. Completed runs are inspected before persistence.

The inspector reports whether a historical policy or check set differs from the current evaluation. The projector explicitly warns that changed expectations do not prove a website correction, and removed targets/obligations are not resolved failures. A regression removes a failing target declaration and verifies its archived failure plus this scope-change narrative. Owner-policy revisions remain supported without silently changing the population identity.

Only actual current failed checks produce findings; current evaluation time must match the final run clock. Native captures, private alternate targets and provider/JSON-LD bodies remain outside canonical reports. Existing limitations remain: URL Inspection is a provider snapshot, local captures do not establish provider index state, hreflang/target checks do not establish content equivalence, and limited JSON-LD checks do not guarantee rich results. Numeric counts describe supplied captures, not independent executions or quality scores.
