# GA4 supplied row metrics — development checkpoint

The development report assembler replays retained GA4 Data API supplied exports and projects a bounded allowlist of count metrics (active users, total users, new users, sessions, page/screen views and event count). Each observation binds one provider row and metric; no cross-row sum or inferred property total is produced. Original dimension values, filters, locators and payloads remain outside customer JSON/Markdown/HTML; output records dimension count, whether filters are present, the supplied reporting timezone and date window. Row numbers are opaque and do not identify a city or query without separately authorized mapping.

Only native metric definitions without expressions, invisible flags or unknown fields are supported. Google's [Metric documentation](https://developers.google.com/analytics/devguides/reporting/data/v1/rest/v1beta/Metric) explains that expressions can define metrics under a supplied name; a name alone cannot prove semantics. Numeric values must be nonnegative safe integer strings with TYPE_INTEGER. Other values, including currency/rates and unsupported or unsafe numbers, are withheld and accompanied by fixed instructions. Multiple date ranges, cohorts and comparisons are unsupported. At most 100 distinct-input rows per target are admitted; overflow rejects rather than truncates.

Complete supplied pagination and a valid single reporting timezone are required. Thresholding, sampling, other-row loss, truncation and restriction flags are reported as supplied declarations; missing values remain unknown. Malformed quality metadata or metric restrictions withhold the numeric rows. Other metadata is explicitly not assessed. Values use approximate precision and are not provider-authenticated or claims of complete population, causality or business impact. Source-owner gaps remain separately relevant. [Google's ResponseMetaData reference](https://developers.google.com/analytics/devguides/reporting/data/v1/rest/v1beta/ResponseMetaData) describes the source fields.

Identical inputs share a stable retained representative; competing or expired inputs are historical. Declined/invalid requests withhold values; a V1 parent revision requiring previously disclosed observations fails closed until an authorized history disposition exists. Review is needed before integrating governed research or delivery/storage authority. This work does not add live provider credentials, GA4 account authenticity, full measurement semantics, Bing metrics, production remediation or commercial release.

Independent review reproduced and closed metric-expression mislabeling and malformed quality-array gaps. Tests cover supplied row values and privacy across JSON/Markdown/HTML, filters, missing/invalid timezone, unknown metrics, expressions, unsafe values, types, pagination, sampling/thresholding, malformed or restricted metadata, aliases, competing/expired sources, actual parent revision and multipage identity. These are synthetic developer tests, not enterprise precision/recall or native-host acceptance.
