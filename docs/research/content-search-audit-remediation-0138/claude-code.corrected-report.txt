## 3. Material findings

### F02 — Redirect loop between `/old` and `/new` (dossier 02) · SEO · high severity, high confidence, observed

Evidence:

- 02-route.md:3 · `Publisher intent: /old should redirect once to an accessible /new product page.`
- 02-route.md:5 · `GET https://store.example.invalid/old -> 301 Location: https://store.example.invalid/new`
- 02-route.md:6 · `GET https://store.example.invalid/new -> 301 Location: https://store.example.invalid/old`
- 02-route.md:7 · `An older sitemap export lists /new as the preferred URL. No final successful response or engine-selected canonical is available.`

Rationale: both responses come from the same deployment and time. The intended destination redirects back to its source, so neither URL resolves, contradicting the stated single-redirect intent. The sitemap's preferred URL is itself a redirect. Any client that needs the page (users, search crawlers, AI retrieval) depends on a final response; that downstream effect is inferred, not observed.

Checks: `seo-canonical` fail. `seo-response` stays unknown because no final response was captured (a 301 is nonfinal).

Proposed action (separate implementation task): remove the `/new` → `/old` redirect rule so `/new` serves the product page; keep the single `/old` → `/new` 301; confirm a current sitemap still lists `/new`.

Verification: recapture `GET /old` and `GET /new` without auto-following redirects. Expect one 301 from `/old` to `/new`, and a final 2xx with product content from `/new`.

Not established: engine-selected canonical, index status, how old the sitemap export is.

### F01 — `noindex` header contradicts meta robots and indexing intent (dossier 01) · SEO · high severity, high confidence, observed

Evidence:

- 01-visibility.md:3 · `Publisher intent: this public product page should be eligible for Google indexing.`
- 01-visibility.md:5 · `Robots.txt permits Googlebot access to /product. Response header: X-Robots-Tag: noindex.`
- 01-visibility.md:6 · `Raw HTML head: <meta name="robots" content="index,follow"><link rel="canonical" href="https://store.example.invalid/product">`
- 01-visibility.md:7 · `No Search Console or actual index observations are supplied.`

Rationale: the same capture carries two index directives that disagree, and the header one opposes the stated intent. Current engine handling of conflicting directives was not verified in this offline review; no engine consequence or actual index state is established. The conflict itself is observed.

Checks: `seo-index-controls` fail. `seo-response` pass (HTTP 200 captured; that is not index evidence). `aio-crawler-policy` pass for Googlebot only.

Proposed action (separate implementation task): remove `noindex` from the `X-Robots-Tag` header served for `/product`. Keep the robots.txt allowance.

Verification: recapture the response headers and raw HTML for `/product`; confirm no `noindex` in any `X-Robots-Tag` header or robots meta element. Index status needs separate URL-level index evidence from the publisher's Google account; I have not verified which tool or export is available to them.

Clean within this dossier: the canonical element points to the captured URL itself. Whether any HTTP `Link` canonical exists is unknown (only one header was reported), so `seo-canonical` stays unknown.

### F03 — JSON-LD price contradicts the visible confirmed price (dossier 03) · SEO + AIO, consolidated · high severity, high confidence, observed

Evidence:

- 03-offer.md:3 · `The publisher confirms the visible US monthly price below is the current policy.`
- 03-offer.md:4 · `Visible content: Example plan, United States monthly billing, USD 29 before taxes.`
- 03-offer.md:14 · `"price": "19",`
- 03-offer.md:15 · `"priceCurrency": "USD",`
- 03-offer.md:21 · `No feature-eligibility test, Search Console or observed rich result is supplied.`

Rationale: on the same page, market and capture time, the machine-readable offer states 19 USD while the visible, publisher-confirmed price is USD 29. This single defect fails two rules — structured data disagreeing with visible content (SEO) and inconsistent entity facts for machine readers (AIO) — and is recorded once. Name and currency agree.

Checks: `seo-structured-data` fail, `aio-entity-consistency` fail.

Proposed action: change `offers.price` from `"19"` to `"29"` and trace the template or data source that emitted 19 so visible and structured prices share one record.

Verification: recapture the page for the same market, extract the JSON-LD and confirm `offers.price` equals the visible price and the current policy.

Not established: syntax validity, rich-result eligibility, or any observed search appearance. The visible copy itself is clean against the publisher's confirmation.

### F05 — Draft overstates free ticket changes (dossier 05, Vietnamese) · Content quality · high severity, high confidence, observed

Evidence:

- 05-huong-dan.md:4 · `Bản nháp: Tất cả khách hàng được miễn phí đổi vé, không cần báo trước.`
- 05-huong-dan.md:5 · `Chính sách hiện hành: Chỉ hạng Thành viên được miễn phí đổi vé. Yêu cầu đổi phải gửi trước giờ khởi hành ít nhất 24 giờ. Các hạng khác áp dụng mức phí trong bảng giá riêng; bảng giá đó chưa được cung cấp.`

Rationale: the draft makes two assertions and the supplied current policy contradicts both. Free changes apply only to the Thành viên tier, not all customers; and the request must be sent at least 24 hours before departure, not without notice. Other tiers pay a fee.

Checks: `quality-claims` fail. `aeo-answer-evidence` stays unknown: no question set or stated answer purpose was supplied, and I did not invent one.

Proposed wording (a proposal, not a quotation, not applied): "Chỉ khách hàng hạng Thành viên được miễn phí đổi vé. Yêu cầu đổi phải gửi trước giờ khởi hành ít nhất 24 giờ. Các hạng khác áp dụng mức phí theo bảng giá riêng."

Verification: compare the revised draft with the current policy on tier scope, the 24-hour minimum and the fee reference.

Not established: fee amounts for other tiers (the fee table was not supplied, so the draft should not state amounts yet), and the policy's effective date.

### F04 — Two "current" pages disagree on Starter storage (dossier 04) · Content quality + AIO + Portfolio, consolidated · high severity, high confidence that they conflict; correct value unknown

Evidence:

- 04-policy.md:3 · `Both pages describe the same Starter plan, market, monthly billing period and policy version 2026-10-01.`
- 04-policy.md:4 · `/product: Starter includes 1000 storage units per month.`
- 04-policy.md:5 · `/blog/starter-guide: Starter includes 1500 storage units per month.`
- 04-policy.md:6 · `Both pages are labeled current. The authoritative entitlement table is unavailable. No query/page performance export is supplied.`

Rationale: plan, market, billing period and policy version are stated to be identical, so the two values cannot both be right. At least one page misstates an entitlement, and a reader or answer engine drawing on both gets conflicting facts. This is one issue across three dimensions, recorded once.

Checks: `portfolio-contradictions`, `quality-claims` and `aio-entity-consistency` all stay unknown, because resolving them needs the authoritative record. The finding is persisted against those unresolved checks.

Proposed action (investigate): obtain the entitlement table for policy version 2026-10-01. **If** it shows which value applies, correct whichever page disagrees so both state the same allowance.

Verification, under the same condition: re-read both revised pages against the table and confirm identical value, plan, market, period and policy version.

Not established: which page is wrong (possibly both). Cannibalization or duplication between the two pages is not assessed; there is no query/page evidence.
