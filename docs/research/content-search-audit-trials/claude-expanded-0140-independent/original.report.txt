## 3. Material findings

### F1. Dossier 01: response header `noindex` contradicts the intent that the page be indexable

- Dimension: SEO. Severity high, confidence high, observed. Affected item: `targets/01-visibility.md` (page `https://store.example.invalid/product`, capture 2026-11-10T08:00:00Z, HTTP 200).
- Evidence:
  - `01-visibility.md:3` — `Publisher intent: this public product page should be eligible for Google indexing.`
  - `01-visibility.md:5` — `Robots.txt permits Googlebot access to /product. Response header: X-Robots-Tag: noindex.`
  - `01-visibility.md:6` — `Raw HTML head: <meta name="robots" content="index,follow"><link rel="canonical" href="https://store.example.invalid/product">`
- Rationale: the header says noindex, the HTML says index, and the publisher wants the page indexable. The two directives conflict with each other and the header conflicts with the intent. Google's robots meta documentation (the source linked from the skill's rule registry; recalled, not re-read in this offline audit) treats the header as an indexing directive and applies the more restrictive rule when directives conflict, so the expected consequence is that the page is kept out of the index. That consequence is an inference. Whether the page is actually indexed is unknown:
  - `01-visibility.md:7` — `No Search Console or actual index observations are supplied.`
- Proposed action: stop sending `X-Robots-Tag: noindex` on `/product` (find which server, CDN or framework layer adds it). Keep the meta robots value and canonical as they are. Changing headers is a separate implementation task.
- Verification: take a new raw HTTP capture of `/product` and confirm the response carries no `X-Robots-Tag` noindex value and the meta robots is still `index,follow`. Index status needs separate index evidence.
- Clean components in this dossier: the robots.txt decision for Googlebot matches the intent; the canonical is self-referential (check passed for the declared signal only); the captured status is 200 (check passed; not index evidence).

### F2. Dossier 02: `/old` and `/new` redirect to each other

- Dimension: SEO. Severity high, confidence high, observed for the captured deployment and time. Affected item: `targets/02-route.md`.
- Evidence:
  - `02-route.md:3` — `Publisher intent: /old should redirect once to an accessible /new product page.`
  - `02-route.md:5` — `GET https://store.example.invalid/old -> 301 Location: https://store.example.invalid/new`
  - `02-route.md:6` — `GET https://store.example.invalid/new -> 301 Location: https://store.example.invalid/old`
- Rationale: the two captured responses form a loop, so neither URL returns a page. This contradicts the intent of one redirect ending at an accessible `/new`. A user or crawler following these responses never reaches the product page.
- Proposed action: remove the 301 from `/new` to `/old` so `/new` serves the page directly; keep the single 301 from `/old` to `/new`. This is a separate implementation task.
- Verification: re-capture both requests on the same deployment. `GET /old` returns one 301 to `/new`; `GET /new` returns a final successful response with no `Location` back to `/old`.
- Left unknown: canonical selection and index state.
  - `02-route.md:7` — `An older sitemap export lists /new as the preferred URL. No final successful response or engine-selected canonical is available.`
  - The sitemap export is undated and described as older, so it is context, not a current canonical signal. The helper's HTTP-status check stays unknown because a 301 is a non-final response; the finding is persisted against that check.

### F3. Dossier 03: JSON-LD price contradicts the visible, publisher-confirmed price (one issue, three dimensions)

- Dimensions: SEO (structured data), AIO (entity consistency), content quality (claim support). Severity high, confidence high, observed. Affected item: `targets/03-offer.md`. This is one defect counted once; it fails three rules.
- Evidence:
  - `03-offer.md:3` — `The publisher confirms the visible US monthly price below is the current policy.`
  - `03-offer.md:4` — `Visible content: Example plan, United States monthly billing, USD 29 before taxes.`
  - `03-offer.md:14` — `"price": "19",`
- Rationale: on the same page, market and capture time, people read USD 29 and machines read 19 USD. The publisher confirms the visible price, so the structured data is the wrong side. Search engines and AI systems that read the JSON-LD receive a price the publisher does not offer. How any engine actually displays or uses it is not observed:
  - `03-offer.md:21` — `No feature-eligibility test, Search Console or observed rich result is supplied.`
- Proposed action: change `offers.price` from `"19"` to `"29"`; `priceCurrency` stays `USD`. Leave the visible copy unchanged. This is a separate implementation task.
- Verification: re-read the JSON-LD block in a new capture of the same page and market and confirm `offers.price` equals the visible US monthly price. Rich-result eligibility is a separate check and is not established by this fix.
- Clean component: the visible price statement is supported by the publisher confirmation.

### F4. Dossier 04: two current pages state different Starter storage allowances (one issue, three dimensions)

- Dimensions: portfolio (contradiction), content quality (claim support), AIO (entity consistency). Severity high, confidence high that the conflict exists; which value is correct is unknown. Affected item: `targets/04-policy.md` (pages `/product` and `/blog/starter-guide`).
- Evidence:
  - `04-policy.md:3` — `Both pages describe the same Starter plan, market, monthly billing period and policy version 2026-10-01.`
  - `04-policy.md:4` — `/product: Starter includes 1000 storage units per month.`
  - `04-policy.md:5` — `/blog/starter-guide: Starter includes 1500 storage units per month.`
  - `04-policy.md:6` — `Both pages are labeled current. The authoritative entitlement table is unavailable. No query/page performance export is supplied.`
- Rationale: plan, market, billing period and policy version are the same, so no date or market difference explains the two numbers. At least one page misstates the entitlement, and a reader or an answer system can take either number as current. The audit cannot say which page is wrong.
- Proposed action (conditional): **if the owner supplies the authoritative Starter entitlement table for policy version 2026-10-01**, correct whichever page (or both) disagrees with it so the two pages state the same allowance. Until then the action is to obtain the table; do not edit either page on a guess.
- Verification (same condition): compare each revised statement with the table for the same plan, market, billing period and policy version, and confirm the two pages agree.
- Left unknown: the three associated checks stay unknown because no authoritative record exists; the finding is persisted against them. Duplication or cannibalization between the two pages is not assessed: no query/page data is supplied and the full page bodies are not in the dossier. No consolidation is proposed.

### F5. Dossier 05 (Vietnamese): draft overstates free ticket changes

- Dimension: content quality. Severity high, confidence high, observed. Affected item: `targets/05-huong-dan.md`. Audience and language are Vietnamese; the comparison is limited to draft versus supplied policy, as the dossier instructs.
- Evidence:
  - `05-huong-dan.md:4` — `Bản nháp: Tất cả khách hàng được miễn phí đổi vé, không cần báo trước.`
  - `05-huong-dan.md:5` — `Chính sách hiện hành: Chỉ hạng Thành viên được miễn phí đổi vé. Yêu cầu đổi phải gửi trước giờ khởi hành ít nhất 24 giờ. Các hạng khác áp dụng mức phí trong bảng giá riêng; bảng giá đó chưa được cung cấp.`
- Rationale: the draft is wrong on two points. It extends free changes from the Member tier to all customers, and it drops the requirement to send the request at least 24 hours before departure. A customer relying on the draft would expect a free change the policy does not grant.
- Proposed action: rewrite the sentence in Vietnamese. Proposed wording (auditor's proposal, not a quotation): "Chỉ khách hàng hạng Thành viên được miễn phí đổi vé. Yêu cầu đổi phải gửi trước giờ khởi hành ít nhất 24 giờ. Các hạng khác áp dụng mức phí theo bảng giá riêng." Do not state fee amounts; the fee table was not supplied.
- Verification: compare the revised sentence with line 5 of the dossier for eligibility, notice period and the reference to the separate fee table.
- Left unknown: AEO answer support (the dossier does not say what customer question or page the draft serves) and any performance effect:
  - `05-huong-dan.md:6` — `Không có dữ liệu traffic, thứ hạng hoặc tỷ lệ chuyển đổi.`
