## 4. Material findings

### F-02-redirect-loop — dossier 02 (SEO, critical)

Evidence:

- 02-route.md:3 — `Publisher intent: /old should redirect once to an accessible /new product page.`
- 02-route.md:5 — `GET https://store.example.invalid/old -> 301 Location: https://store.example.invalid/new`
- 02-route.md:6 — `GET https://store.example.invalid/new -> 301 Location: https://store.example.invalid/old`
- 02-route.md:7 — `An older sitemap export lists /new as the preferred URL. No final successful response or engine-selected canonical is available.`

- **Affected:** `/old` and `/new` on store.example.invalid (item 02).
- **Rationale:** each URL permanently redirects to the other in the same deployment and time, so neither request ends at a page. This contradicts the stated intent, and `/new`, which the intent and the older sitemap both prefer, points away from itself.
- **Limits:** the sitemap export is older and not supplied. No engine behaviour is observed.
- **Proposed action:** in a separate implementation task, remove the 301 from `/new` to `/old` so `/new` serves the product page, and keep the single 301 from `/old` to `/new`.
- **Verification:** re-capture both requests. `/old` returns one 301 whose Location is `/new`; `/new` returns a final successful response with the product content and no Location header. Then confirm the current sitemap still lists `/new`.
- **Checks:** `seo-canonical` fail; `seo-response` stays unknown because no final response exists.

### F-01-noindex-header — dossier 01 (SEO, high)

Evidence:

- 01-visibility.md:3 — `Publisher intent: this public product page should be eligible for Google indexing.`
- 01-visibility.md:5 — `Robots.txt permits Googlebot access to /product. Response header: X-Robots-Tag: noindex.`
- 01-visibility.md:6 — `Raw HTML head: <meta name="robots" content="index,follow"><link rel="canonical" href="https://store.example.invalid/product">`
- 01-visibility.md:7 — `No Search Console or actual index observations are supplied.`

- **Affected:** `https://store.example.invalid/product`, capture 2026-11-10T08:00:00Z (item 01).
- **Rationale:** the response header asks for no indexing while the publisher wants the page indexable and the HTML meta tag says index. The two directives disagree, and the header contradicts the intent.
- **Consequence, not verified offline:** my understanding of Google's robots-directive documentation is that a header noindex is honoured and the more restrictive of conflicting directives applies. That documentation was not re-read in this audit.
- **Limits:** whether the page is currently indexed is not observed.
- **Proposed action:** in a separate implementation task, find which layer (server, CDN or application) adds the header and stop sending `X-Robots-Tag: noindex` on this URL. Leave the meta tag and canonical as they are.
- **Verification:** new capture of the same URL: no noindex in any `X-Robots-Tag` header or robots meta tag, status still 200, robots.txt still permitting Googlebot. Confirm indexing separately from index evidence.
- **Clean in the same capture:** HTTP 200; robots.txt permits Googlebot (`aio-crawler-policy` pass for the one stated surface); the canonical tag points to the captured URL (`seo-canonical` left unknown because the full headers and variants are not supplied).

### F-03-schema-price — dossier 03 (SEO, AIO and quality; one issue)

Evidence:

- 03-offer.md:3 — `The publisher confirms the visible US monthly price below is the current policy.`
- 03-offer.md:4 — `Visible content: Example plan, United States monthly billing, USD 29 before taxes.`
- 03-offer.md:14 — `"price": "19",`
- 03-offer.md:15 — `"priceCurrency": "USD",`
- 03-offer.md:21 — `No feature-eligibility test, Search Console or observed rich result is supplied.`

- **Affected:** the Example plan page and its JSON-LD `Product`/`Offer` block (item 03).
- **Rationale:** on the same page, market and capture, the machine-readable offer price is 19 USD and the visible, publisher-confirmed price is USD 29. The visible copy is the supported value; the structured data is the wrong one.
- **Why one finding:** the same mismatch is a structured-data defect (SEO), an inconsistent product fact for machine readers (AIO) and a contradicted factual claim (quality). Three checks fail; one action fixes all three.
- **Limits:** search-feature eligibility and any rich result are untested and unobserved. The block's `url` value was not fetched.
- **Proposed action:** change `offers.price` from `"19"` to `"29"`, keep `priceCurrency` `"USD"`, and fix the template or data source that emits the price so the two cannot drift.
- **Verification:** re-capture the page and compare `offers.price` and `priceCurrency` with the visible price for the same market and billing period against the confirmed policy.

### F-04-storage-conflict — dossier 04 (quality, AIO and portfolio; one issue)

Evidence:

- 04-policy.md:3 — `Both pages describe the same Starter plan, market, monthly billing period and policy version 2026-10-01.`
- 04-policy.md:4 — `/product: Starter includes 1000 storage units per month.`
- 04-policy.md:5 — `/blog/starter-guide: Starter includes 1500 storage units per month.`
- 04-policy.md:6 — `Both pages are labeled current. The authoritative entitlement table is unavailable. No query/page performance export is supplied.`

- **Affected:** `/product` and `/blog/starter-guide` (both inside item 04).
- **Rationale:** two pages labelled current state different allowances for the same plan, market, period and policy version. Both cannot be right.
- **What is not established:** which figure is correct. The authoritative table is unavailable, so neither page is called wrong, and the three related checks stay unknown.
- **Why one finding:** it is a claim-accuracy question (quality), an inconsistent product fact (AIO) and a cross-page contradiction (portfolio).
- **Not claimed:** overlap or cannibalization between the two pages; no query/page data is supplied.
- **Proposed action (investigate):** obtain the authoritative Starter entitlement for policy version 2026-10-01. Once the owner supplies it, correct whichever page disagrees.
- **Verification:** under that same condition, compare the allowance sentence on both pages with the authoritative table; both must match it and each other.

### F-05-doi-ve — dossier 05 (quality, high)

Evidence:

- 05-huong-dan.md:3 — `Chỉ đối chiếu bản nháp với chính sách được cung cấp.`
- 05-huong-dan.md:4 — `Bản nháp: Tất cả khách hàng được miễn phí đổi vé, không cần báo trước.`
- 05-huong-dan.md:5 — `Chính sách hiện hành: Chỉ hạng Thành viên được miễn phí đổi vé. Yêu cầu đổi phải gửi trước giờ khởi hành ít nhất 24 giờ. Các hạng khác áp dụng mức phí trong bảng giá riêng; bảng giá đó chưa được cung cấp.`
- 05-huong-dan.md:6 — `Không có dữ liệu traffic, thứ hạng hoặc tỷ lệ chuyển đổi.`

- **Affected:** the Vietnamese draft sentence (item 05).
- **Rationale:** the draft is wrong on two points in one sentence. It extends free changes to all customers where policy limits them to the Thành viên tier, and it says no notice is needed where policy requires the request at least 24 hours before departure. It also omits that other tiers pay a fee.
- **Limits:** the fee table is not supplied, so no amount can be stated or checked. The review was limited to draft against policy, as the dossier instructs; no search or AI dimension was assessed.
- **Proposed wording (a proposal, not a quotation):** Chỉ hạng Thành viên được miễn phí đổi vé. Yêu cầu đổi phải gửi trước giờ khởi hành ít nhất 24 giờ. Các hạng khác áp dụng mức phí theo bảng giá riêng.
- **Verification:** compare the revised draft with the supplied policy sentence by sentence: eligibility limited to hạng Thành viên, the 24-hour requirement present, other tiers referred to the fee table, and no fee amount that is absent from a supplied table.
