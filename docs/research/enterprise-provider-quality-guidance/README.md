# Provider quality guidance — development checkpoint

A provided export can still be incomplete or have quality limitations. The development report assembler now renders fixed guidance for replay-validated provider gap codes, anchored to each source evidence item. Examples include incomplete GA4 data-stream/key-event pages, missing timezone/currency, incomplete export pagination, potential sampling/thresholding/truncation and restricted metrics. The copy instructs the owner what to supply or verify and does not mark a check passed. Additional unknown gap codes produce generic owner-review guidance rather than interpolating source text.

Capture freshness is labeled separately from validity or assessment acceptance. Quality metadata may be malformed even if original bytes replay correctly; sampling, thresholding and truncation are described as unverified warnings requiring owner validation, not asserted facts. Historical source warnings remain explicitly historical. Declined/invalid requests suppress these source narratives. The canonical source request can remain provided while quality follow-up is described in narrative; this checkpoint does not create a new structured data request or change its status.

Tests use synthetic inputs to verify incomplete configuration guidance despite a provided request, evidence binding, sampling/thresholding warning wording, malformed metadata, stale and declined states, and JSON/Markdown/HTML privacy. Independent review identified and verified the fix for a truthiness-based false-claim risk. Source authenticity, human/AI review identity, automatic source resolution, permission withdrawal, live provider connections, full mixed-module report and commercial acceptance remain open.
