# Candidate 0.3.30 — accessibility history and report assembly

The packaged accessibility inspector now validates complete current/history ownership before exposing projections. The development general assembler supports both accessibility evaluation and generated check evidence through that inspector.

## Corrections

The prior validator accepted any hexadecimal evaluator fingerprint and ran current code under that supplied label. It now requires the supported fingerprint explicitly; unsupported versions require separate assessment or reviewed migration. Current and historical base/row artifacts are regenerated and compared in full, with declared history membership (maximum 100), original scope, lineage and chronology. Global orphan-artifact checks prevent unindexed rows or historical bases from appearing in reports.

Activation is recorded separately from content origin. Same-clock A → B → A reuse remains valid; backdated activation, missing history and rollback indexes reject. Scope narrowing and duplicate populations remain prohibited. The completed run is inspected before persistence.

Request generation is shared with descriptor validation, while permitted lifecycle state and refusal reasons remain explicit. An initial regression exposed that viewport/window key order changed the embedded export-instruction string after save/load. Stable serialization and explicit code-unit ordering now make these descriptors deterministic across hosts. Default-locale sorting is removed.

## Report behavior

The development adapter requires current assessments at the final run clock and emits findings only for actual current failed checks. Historical sample counts remain historical and do not assert current website state. Automated/scenario coverage is restricted to declared rules, states, viewports and windows. The full-manual-coverage check stays unknown; counts are not conformance percentages, independent executions or quality scores.

Canonical reports exclude original axe HTML, selectors and scenario attachment bodies. Canary tests modify native HTML and nested attachment bytes with recomputed hashes, proving the projection uses the assessment rather than serializing source bodies. No supplied author becomes an independent reviewer or authenticated execution.
