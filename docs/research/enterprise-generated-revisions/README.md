# Exact generated report revisions

Development-only `buildStoredGeneratedReportRevision(sourceDirectory, metadata, ancestors, outputDirectory)` builds a fresh customer report from the shared original-source module registry and an explicit root-first chain. Each ancestor binding supplies sourceDirectory, reportDirectory, sourceRunDigest, reportDigest and manifestDigest. Every ancestor is reloaded and replayed from its own source, not trusted as a cached proof. The immediate parent digest is set by the builder. No customer package or release changed.

The provenance inspector accepts up to 32 ancestors. It rejects incomplete/reordered chains, sibling substitution, duplicate report identities, reused run IDs with rewritten source, backwards assessment time, curated content, unsupported module sources and projection mismatches. Canonical parent continuity enforces customer/run ancestry, revision time and retention of original observations. Findings and narrative are regenerated; this API does not claim complete editorial history, and actions/review prose remain unsupported.

Stored loading first validates all binding metadata and stats every source/report artifact before any content read. Per-file size is bounded at 32 MiB, aggregate artifact size at 64 MiB, including repeated source bindings. Parsed canonical model bytes also have an aggregate limit. These checks and the final source/report rechecks are optimistic, not filesystem locks: concurrent file growth or changes after the final check are not atomically prevented. Compiler inventory must remain unchanged during replay. Current compiler compatibility is required; this is not historical evaluator dispatch or code authentication.

All paths refer to externally authorized local content. There is no governed-text preflight, retention grant, public disclosure grant or delivery authorization. Exact chain replay does not imply complete history, retained permissions, remediation, or enterprise commercial acceptance. The encrypted registry's ordered subset comparison still correctly reports revisionChainVerified=false; it has no complete-chain proof API.
